## Mistakes & lessons

| # | Mistake | Class | Rule |
|---|---------|-------|------|
| 1 | `background:` shorthand reset `background-clip: text` → gradient text rendered as solid bars on first verify | Accuracy gap | Always declare `background-clip: text; -webkit-background-clip: text;` AFTER `background:` in gradient-text rules. Shorthand resets the clip to `border-box`. **FLAG FOR CLAUDE.md CODING RULES (blocked headless).** |
| 2 | Diagnosed video `readyState:0` in a backgrounded automation tab for ~3 rounds before Playwright confirmed all 12 actually play | Speed gap | Chrome suspends ALL media in backgrounded/hidden tabs (`document.hidden:true`). `readyState:0` in that context proves nothing — it's the same for every clip. Correct move: go straight to `Playwright currentTime` in a real (non-backgrounded) page. **FLAG FOR CLAUDE.md TESTING RULES (blocked headless).** |
| 3 | `window.scrollTo()` and `scrollTop` blocked in backgrounded tab → multiple failed attempts before discovering wheel scroll works | Speed gap | In automation, if `window.scrollTo` appears to no-op (scrollY stays 0), the page is backgrounded. Use `page.mouse.wheel()` / real wheel events instead. For jumping to a known section, navigate to `#anchor` in the URL. |
| 4 | Stop hook friction — assistant offered options + asked for layout/button pick after interview was complete, instead of making a recommendation and shipping the non-ambiguous piece first | Autonomy gap | When `/goal` says "interview me for questions" and answers are obtained, the interview is done. For implementation choices where user is slow to pick, make a clear recommendation with rationale and implement the highest-impact non-pick-gated piece (e.g., the Aurora button was pick-independent). Don't re-enter an interview loop for the implementation step. |
