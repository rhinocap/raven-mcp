## This session

### Visual rhythm checks added to `audit_page`
**What:** Five new static checks on HTML/CSS source:
- `spacing/base-unit` — % of `gap`/`padding`/`margin` values on a 4px or 8px grid
- `spacing/scale-count` — number of unique spacing values (flags >7)
- `typography/modular-scale` — heading size ratios vs standard scales (minor second → golden ratio); flags if avg deviation >5%
- `typography/line-height-scale` — flags >4 distinct line-heights
- `color/palette-size` — flags >10 distinct hex colors

**Why:** These are the rhythm signals you can derive from source alone. No new deps, drops into existing `audit_page` pipeline.

### New tool: `audit_layout`
**What:** Ingests rendered geometry `{elements:[{selector, rect, computed}], viewport}` and scores:
- **Alignment** — clusters left edges within 2px; reports alignment columns, one-offs, % of elements on a shared column
- **Gap rhythm** — computes vertical gaps between horizontally-overlapping siblings; reports median, stdev, coefficient of variation
- **Optical balance** — torque-based (area × distance from content-bounds midline), normalized against max possible torque so perfectly-centered mass reads as 0% skew

Stateless. Call with no args → returns a DevTools snippet that copies `{elements, viewport}` JSON to clipboard. Call again with that JSON → scored report.

**Why:** The spacing/alignment/composition signals that aren't visible in source. Works for the primary use case (local HTML already rendered in a browser).

**Tested:** Synthetic good layout → 3 passes (single alignment column, 24px median gap CV 0.27, balance 1%). Synthetic bad layout → alignment warn (0% aligned across 6 left edges), rhythm borderline (CV 0.49), balance 10%.

**Pushed:** not yet — awaiting Andrew's OK.

## Design decisions & gotchas
- **Torque must be normalized.** First pass: `|L-R| / (L+R)` — broken when most mass sits exactly on the midline (small off-axis element reads as 100% skew). Fix: normalize against `totalArea × contentHalfWidth` (max possible net torque).
- **Balance midline = content bounds, not viewport.** Otherwise an intentionally-left-anchored content column on a wide viewport reads as "left-heavy." Compute from `min(x)` and `max(x+w)` of observed elements.
- **Alignment threshold is ratio, not column count.** 100% of elements on a single shared column IS perfect alignment — don't require ≥2 columns.
