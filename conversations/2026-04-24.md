### Install-count investigation
**What:** Pulled npm download stats since launch (2026-04-12). Total: 676 over 12 days. Spikes: launch (Apr 12-13: 355), v1.2.0 release (Apr 22: 133), v1.3.0 release (Apr 23: 131).
**Insight:** npm download count vastly exceeds the ~200 install pings in Resend because npx auto-updates. Every time `npx -y raven-mcp` starts and sees a newer version, it re-pulls. So each release publish triggers ~130 auto-pulls from existing users. Resend ~200 = closer to true unique-human install count. npm 676 = engagement (existing users actively running Claude on release days).
**Takeaway:** On release days each subsequent release converts ~65% of the user base into a re-pull. Strong signal that posts drive real activation, not vanity impressions.

## Mistakes & lessons

| Mistake | Type | Rule |
|---|---|---|
| Walkthrough listed `cp` then `launchctl load` as separate steps. Andrew ran only the load. | Comm gap | **For multi-step shell sequences where step N depends on step N-1, prefer `&&`-chained one-liners over numbered lists. Forces ordering, surfaces failure point clearly.** |
| Initial HN smoke test (with default Algolia settings) returned 65 "matches" that were all fuzzy-match noise. I'd set up the source without verifying with real data first. | Accuracy gap | **For any fuzzy-search API (Algolia, Reddit search, Elasticsearch), assume default tolerance is on. Test with a known-noisy term in a smoke step before declaring the source done.** |
| GitHub issues endpoint silently broke last year (now requires `is:issue` qualifier). I built against my mental model of the API, not the current docs. Caught at smoke-test, but if smoke had been less thorough this would have shipped silent-failing. | Accuracy gap | **For external APIs that change semantics over time, run one query against the live endpoint as part of the build smoke test. 422s, 410s, and silent schema changes are common.** |
