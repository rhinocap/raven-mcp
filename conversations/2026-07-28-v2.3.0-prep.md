## Two things I got wrong

**`./scripts/release.sh minor --dry-run` ran a real release.** Dry-run is an
env var (`DRY_RUN=1`), stated plainly in the usage block at lines 9–13. `BUMP`
took `minor`; `--dry-run` landed in `$2` and was silently ignored. I invented a
flag instead of reading eleven lines of the script I was about to run. It
bumped four files to 2.3.0 and rebuilt both `.mcpb` bundles before dying at
`npm publish` (E404, downstream of the E401 auth). Nothing irreversible: npm
untouched, no commit, no tag. The dirty tree it left would have blocked
Andrew's own run, since `release.sh` refuses one.

The recovery: `git checkout --` was blocked by the destructive-op guard, which
was right to. `git stash push -- <paths>` gets the same clean tree and keeps
the changes recoverable — it's in `stash@{0}`, labelled. Prefer stash over
checkout for undoing machine-generated tree state.

**Scope.** I read a pasted localhost URL as a bug report and worked it — in
`andrewcunliffe-portfolio`, where a parallel session was live. One file edited
and left uncommitted (`StoryDevClient.tsx`), everything else read-only, no
commits, no pushes. A URL is not an assignment, and this session is raven-mcp.
