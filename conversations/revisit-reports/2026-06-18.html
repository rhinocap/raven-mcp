Mistakes & lessons
Speed gap
npm release: EOTP → passkey 404 → automation token (4 round-trips)
release.sh hit an EOTP gate; the npm web-auth URL returned 404; the passkey flow is WebAuthn not TOTP so --otp= is wrong; total ~4 back-and-forth turns before landing on "automation token." Rule captured in the release skill: always npm whoami first; if E401/EOTP, skip interactive auth entirely and generate an Automation token (type matters — not Publish, not Granular, Automation).
Speed gap
sed batch silently no-oped on skill rename
The sed loop to update name: frontmatter in 11 renamed dirs passed $DIRS as the path arg — the shell treated the whitespace-separated list as one word, so sed ran on a nonexistent path and exited 0. Required a re-run with the list inlined. Rule: always inline path lists in bash batch ops; never rely on variable word-splitting in non-interactive sh. Verify by grepping the result before declaring done.
Accuracy gap
Claimed "auto-save hook commits locally" — it hadn't
Stated the auto-save hook had committed the staged files; git status showed they were staged but not committed. Minor — caught immediately. Rule: never assume the auto-save hook fired; always confirm with git status before claiming committed state.
Staleness catch
iOS 26.x sim-runtime rule is factually wrong on this machine
CLAUDE.md says "Apple ships no iOS 26.x sim runtime" — but xcrun simctl list runtimes shows 26.4 and 26.5. The rule's intent still holds (device-verify even when a sim is available, because sim-level render/scroll bugs don't reproduce on device), but the premise is stale. Follow-up: soften to "even with a 26.x sim runtime present, 26.x-specific scroll/layout bugs still require device verification." Not a mistake this session (I caught and flagged it), but a data-staleness pattern to watch.
