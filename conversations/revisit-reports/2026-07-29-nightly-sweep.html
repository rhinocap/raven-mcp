What the backlog actually was

Sixty-nine eligible logs, twenty-four already credited in metrics.md, forty-five un-revisited. Coverage had to be reconciled by full filename rather than by date, because several dates carry multiple logs. Two calls worth recording: 2026-06-24-site-awardify and 2026-06-25-revisit are one covered session (the second is the first one's retrospective output), and the 2026-07-21/24 metrics column claims to cover four dates while its content — a coachmark-tour thread plus morven-loop it109-171 — matches none of the eight logs in that range. Those eight were counted un-revisited. The false claim is left in place: it is a historical record, not a bug to silently rewrite.

The prescribed transcript lookup does not work tooling gap

The documented disambiguator is grep -l '<log-slug>' ~/.claude/projects/<repo>/*.jsonl, with "exactly one match is authoritative." Run across all 45 slugs against 135 transcripts, it resolved to exactly one file zero times — hit counts ran from 2 to 50 per slug.

The reason is structural, not incidental: every later session that reads a session log quotes its filename, so the slug propagates into far more transcripts than the one that wrote it. Slug-grep is not an index. All 45 were therefore revisited from their session logs, per the fallback instruction.

The fix: a conversations/.transcript-index.tsv mapping log filename → session UUID, written by the session-log step itself — the writing session is the only party that knows its own id for free. Failing that, key on cwd plus the first-user-turn timestamp range. Filed in the ideas log.

The one repeated mistake
Surface identity 6 occurrences

Four wrong-surface misses across three consecutive video sessions (07-20, 07-21, 07-22), plus a cross-repo scope breach on 07-28 and another on 07-17. Individually each reads as a slip. Together they are one rule.

Footage of /raven-design was called "the Raven Design Playground" twice — the route matched, the product chrome matched, and the canvas actually loaded was Marginalia. When corrected, the next move was to rebind an older localhost URL without rendering it; that page was Marginalia too. Correcting one wrong URL by blindly reaching for an earlier one landed on the same wrong page.

Route, chrome, and panel names are shared across surfaces of the same product, so every cheap identity signal returns a false positive. The only signal that can fail is page-specific rendered content.

The 07-28 variant is the same error pointed at a repo instead of a page: a pasted localhost URL was read as a bug report and worked — in andrewcunliffe-portfolio, where a parallel session was live. A URL is not an assignment, and the session has a lane.

Claiming a surface you did not pull 3 sessions

check-site-drift diffs repo files against repo files. It stayed green while npm raven-mcp@2.2.9 served 100 tools, the published README said 99, and the repo said 105. Separately, mcp.ravenmcp.ai served a version seven minors stale — not caching, but a Vercel domain pinned to a non-main gitBranch while every push deployed successfully.

Repo-consistent, published-consistent, and deployed-consistent are three claims that fail independently. The guard covered one and read as covering all three. Verify the one you are asserting: npm pack and grep the shipped dist/, probe the host for its own version, read the domain's gitBranch before blaming caching.

Theory before instrumentation 2 fixes wasted

Two fixes shipped on an unfalsifiable compositor-hit-testing theory before live forensics found Lenis.setScroll firing inside a single wheel event (07-23). Synthetic dispatch and CDP are unfaithful for that class of bug. Event counters and stack-trace wrappers on the suspected mutator found it in one pass.

Why seven are amendments, not additions trigger set preserved

Amending keeps the loaded file inside its budget — ~/.claude/CLAUDE.md went 24,058 → 28,954 bytes against a ~30 KB ceiling — but the real reason is the trigger set. A new bullet placed next to an existing one invites a later tidy-up that merges them and quietly drops cases. Appending the new clause onto the bullet that already owns the failure class means every case that fired before still fires.

That ceiling is also why three further findings went to ~/.claude/reference/ instead of the loaded file: Playwright's isMobile: true invalidating every geometry assertion in a run, getBoundingClientRect() >= 44 not proving a 44px tap target, and Codex's 50-tools-per-MCP-server cap with its backwards approval_mode="approve" naming.

A lesson that must not be resurrected
Delegate-by-default is REVERSED superseded

2026-07-02-taste-interview-robust.md records: "Delegate-by-default, main-loop-implement is the exception needing justification." The current <operating-model> says the opposite, because delegate-by-default is precisely what produced the agent-self-report failure class — the single largest measured cause of first-attempt-accuracy loss.

The current rule wins. Recorded here and in metrics.md so a future sweep reading that log does not re-promote the reversed version.

What would make this faster
Three things, all mechanical
  • Make the cadence real. Forty-five logs accumulated over ~3.5 months while the sweep was assumed to be running. No instance can self-schedule past an hour — this needs a launchd LaunchAgent, on the pattern of com.accunliffe.claude-improve-pipeline.plist.
  • A coverage file that can't lie. Coverage currently lives in metrics.md column headers, which are prose and go stale silently. A conversations/.revisited.txt of log filenames turns "un-revisited" into a grep -vxF. Most of this sweep's time went to that reconciliation.
  • A transcript index. As above — the writing session knows its own UUID; nothing else can reconstruct it cheaply.
