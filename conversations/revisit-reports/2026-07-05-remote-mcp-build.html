What shipped — v1.16.0
Phase 0 — additive buildServer() factory Shipped

The module-level McpServer singleton could only connect() once (SDK issue #961), so stdio and the new HTTP transport needed separate server instances from the same registration code. Solved additively — stdio's existing behavior is untouched.

Phase 1 — 45 stateless tools live on the no-auth remote endpoint Shipped 4 adversarial rounds

REMOTE_GATED_TOOLS + isRemoteRuntime() — a one-way latch — gate filesystem, local-store, and side-effecting tools off the anonymous remote surface entirely, rather than patching each tool individually. Verified by test/remote-store-invariant.test.mjs and a golden tool-count hash. Took 4 rounds of Codex adversarial review to close: fs-read/SSRF/compute-DoS, path traversal, a local-store read/write oracle, and side-effecting-tool abuse, each a genuinely distinct hole the previous round's fix didn't cover.

Phase 3 — 5 browser-dependent tools via a hardened, proxied Chromium Shipped Adversarially verified

An in-process, memoized SSRF-safe egress proxy (DNS-rebind-safe validateAndResolve) in front of a @sparticuz/chromium + playwright-core launch, with proxy + hardening flags. A socket-teardown race was found and fixed in the adversarial pass.

P4.0 — async TasteStore interface, byte-identical stdio Shipped Self-caught regression

FsTasteStore / ClosedTasteStore with a .describe() method for byte-identity-preserving error messages. Self-caught its own regression (Item C) before shipping rather than papering over the divergence.

codex:codex-rescue is not resumable Repeat — bumped to 5×

Hit twice more this session (P4.0 verify, cinematic-feature verify): the rescue agent is a pure single-invocation forwarder that launches a detached Codex task and returns immediately. Trying to "resume" it for a blocking result gets an explicit refusal — "I am not permitted to call status, poll, block, or fetch results." Correct pattern: poll the on-disk job-state JSON directly, or arm a background Bash watcher.

Over-broad trigger regex, self-shipped defect Caught by Codex, fixed

First-draft cinematic-feature trigger patterns (cinematic (video|film|clip), video[- ]?led hero) matched non-AI and anti-AI notes, incorrectly pushing paid-Higgsfield guidance. Existing tests had actually blessed these broad matches as intended positives. An independent Codex adversarial pass caught it; fixed by tightening the regex, flipping 4 tests to negatives, and adding explicit false-positive tests.

Self-caught, not shipped

A redirect-to-cloud-metadata SSRF probe reported a spurious FAIL — its own leak-detector matched the echoed input URL rather than real leaked content. Investigated rather than accepting the fail, wrote a corrected detector, re-verified genuinely on the live deployment. A stray literal file named 0 (misread shell redirect around an env var in a smoke test) was caught and removed pre-commit.
