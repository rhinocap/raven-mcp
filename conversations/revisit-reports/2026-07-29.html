The diagnosis

Fable's framing, adopted over mine — as the leading hypothesis, not an established cause: the friction is a measurement problem, not rules-versus-harness. Attributing it cleanly needs a fixed-rubric sample across future sessions, which does not exist yet. The scoreboard rewarded never asking a question and rewarded catching errors after the fact — so the corpus grew 18 post-claim verification bullets against roughly one pre-attempt clause. All four dominant failure classes occur before the first attempt. Weight moved forward: a ≤10-line spec naming every file, surface, capability axis, and human gate before the first edit.

Autonomy is a band, not a maximum Rebound

97–99% was being read as a win. It was a symptom: load-bearing questions suppressed and paid back as rework. The band is now ~90–95, with roughly one question per ten tasks budgeted and expected. Below 90 and above 95 are equally off-target.

Primary finding
Count it — don't ask it Autonomy gap

I closed a findings pass with two open questions: how much of the superpowers plugin does he use, and how should the fragmented memory pools be fixed. He returned both as counter-questions.

"1. Memory is fragmented can't you use graphite or another knowledge graph for this? 2. I honestly don't know how much I use, can you not measure it?"

Both were countable, and counting took minutes. His answer would have been a guess where mine could be exact. The rule now triggers on any question containing how much / how often / how many / do you usually: measure first, then ask only what the numbers leave genuinely open. The budgeted question is for preferences and decisions — never for offloading measurement.

What the measurements said
Superpowers: 1.7%

625 skills on disk, 237 Skill invocations across 400 transcripts, of which superpowers:* was 4 — two distinct skills, three of them systematic-debugging. For scale, design-judge was 105. Fixed with one CLAUDE.md line subordinating the "1% chance → you ABSOLUTELY MUST invoke before any response" mandate, rather than disabling the plugin: the skill defers to CLAUDE.md by its own text, and disabling would cost the most-used superpowers skill. Only invocation frequency was measured — value was not, so keeping it is a default-setting judgment, not a proven claim.

Memory: consolidation prohibitively expensive

218 of 397 memories are cross-cutting — a pre-promotion snapshot; with this session's four new files plus a parallel session's landings the pools now hold 229 of 405. Auto-loading all bodies is ~90,597 tokens per session; the index alone is ~17,223 — prohibitive under the current context budget, not technically impossible, and estimated as chars ÷ 4 rather than counted by a tokeniser. Retrieving only what the message matches is ~200 tokens a turn. This reversed my own recommendation from earlier in the same session, which had proposed the migration without ever costing it.

Mistakes & lessons
I narrowed the done-gate and called it a re-binding Worst defect Accuracy gap

The original triggered on any substantive completion claim, including specs, plans, audits and research. Mine triggered on four literal words — so "ready", "complete" and "all checks pass" silently stopped firing it. Introduced into the one rule whose entire purpose is preventing false-completion claims, and found by an adverse pass after I had read my own edit twice.

Rule: when rewriting a rule or guard, diff the trigger SET, not the prose. Replacing a class trigger with an enumeration is always a narrowing.

The cwd penalty was a no-op Accuracy gap

basename(dirname("/Users/accunliffe/projects/raven-mcp")) is projects — a substring of every path under ~/.claude/projects/. All 223 entries got the same penalty, so it cancelled to zero. Same class: IDF_FLOOR = 6.0 was commented "~1 very rare term" when a unique term actually scored 5.38 — a floor no term could reach.

Rule: verify a threshold, penalty or filter by measuring its effect on real output. If you can't name the number that changes when the tunable is wrong, it isn't verified. Normalise anything denominated in a corpus-size-dependent unit.

Three of seven promotions were false Accuracy gap

Claimed as landed on a "session-loaded surface" when they were filed only in the canonical cross-project pool — which does not auto-load inside a repo session. Reachable, not loaded. Fixed by promoting the rule text itself into CLAUDE.md and keeping the long form in memory.

I reported a precision figure I had not measured Retracted Accuracy gap

"~70% precision" was an eyeball, tuned twice on its own 21-prompt sample with no holdout — and it reached a public document before being withdrawn. The replacement false-negative harness then proved invalid twice (95%, then 100%): slash-command expansions and the /clear summariser prompt sit in the user role, and batch-written memories all inherit one shared preceding message.

Rule: read the actual input/label pairs before reporting a rate. Report unmeasured over an indefensible number, and never pick whichever of two bad numbers reads better.

A UserPromptSubmit hook — the only hook event that receives the user's message (PreToolUse never does, Stop fires too late). Scores the prompt against every cross-cutting memory's headline and injects the top 6 as pointers. Rarity is measured in unique-term units normalised by log(n), so the threshold means the same thing at 218 memories as at 500 instead of silently loosening as the corpus grows.

Verified against a 9-case failure matrix: malformed / list / string / null stdin all exit 0, corrupt and wrong-shape caches both rebuild, a 1.2MB prompt runs in 0.03s, atomic writes leave no litter, a memory added mid-TTL is recalled without waiting the hour. Cold 36ms, warm p50 20ms, against a 5s timeout.

Honest ceiling, written into the rule itself: retrieval is lexical and silence is its failure mode. "this visual bug" recalls the eyes-first rule; "the six dots at the bottom are misaligned" recalls nothing. Absence of a recall block means nothing matched — never that nothing applied. graphify query --budget is the documented upgrade path, deliberately not the first rung, because 397 headline lines need no artifact kept fresh.
