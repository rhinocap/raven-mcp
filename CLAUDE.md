The three are captured at load via `Function.prototype.call.bind`. What that does NOT buy, and the comment now says so instead of claiming immunity: a `<head>` script poisoning the prototype BEFORE injection still wins, which is unclosable from inside a shared realm. (b) The verdict is CONSUMED on read — a `KeyboardEvent` can be dispatched more than once, and an unconsumed mark let a page replay the user's own commit Enter forever, swallowed every time. One mark, one suppression. (c) **The 100ms bound was not a bound**, because `performance.now` is page-replaceable and the expiry is a subtraction over two of its readings: hand back a large value at `compositionend` and a small one at a much later Enter and the delta is NEGATIVE, which satisfies any `< 100` test forever. `performance.now` is captured at load AND `ravenElapsedSince` returns `Infinity` on a delta that is not a non-negative number — the arithmetic half is the load-bearing one, since a pre-injection swap defeats the capture but not the sign check. **Round 14 then showed the sign check was necessary and never sufficient, and corrected one claim that was simply wrong.** (a) A CONSTANT clock defeats it more simply than a backward one: `performance.now = () => 0` makes every delta exactly `0 - 0`, which is non-negative and passes `< 100` forever. The stamp now records BOTH clocks and elapsed time is the **larger** of the `performance.now` and `Date.now` deltas, so a page must freeze both, pre-injection, to hold the window open; taking the larger also preserves the backward-clock behaviour, since `Infinity` wins. The accepted cost is stated in the comment rather than discovered later: `Date.now` is wall-clock and can step, so an NTP jump of >100ms landing between `compositionend` and the commit keydown expires a marker that should have held — the same false-negative direction the bound already accepts, and rarer. (b) **The overlay no longer claims the verdict is safe from a hostile page, because it is not and never was.** Raven's shadow root is OPEN, so a page reaches the field through `shadowRoot` and dispatches a synthetic `compositionstart`/`compositionend` pair that arms the marker without touching any prototype — it feeds the mechanism rather than tampering with it, which the WeakSet capture does nothing about. `event.isTrusted` on the arming `compositionend` would close it and is deliberately NOT used: a page that can dispatch into the shadow root can also `remove()` the host, read every keystroke in the panel, and synthesise the Send click, so the forged verdict (which only ever SUPPRESSES one Enter) is strictly less than what that attacker already has. **This guard is a correctness mechanism against the browser's own event ordering, not a security boundary against the page** — the open shadow root means there is no such boundary to hold. `compositionstart` clears both pieces of state, so a commit in the PAGE's own field cannot disarm Raven's next composition. FOUR residuals are documented in the comment rather than papered over: a mouse-selected candidate, an IME that reports raw pre-edit text as `data` on cancel, a page script that registers a window-capture `compositionend` listener before the overlay loads and calls `stopImmediatePropagation()` (that one cannot be closed from inside the page, only noted), and — added in round 12 — the 100ms bound's own false negative for a very slow typist. **Sol argued the clock is now pure downside and it was kept anyway, deliberately:** ordering does decide the verdict, but without the bound the mouse-selected-candidate residual becomes UNBOUNDED IN TIME (accept a candidate with the mouse, walk away, come back minutes later, press Enter, send eaten), and clearing on blur/`pointerdown` does not rescue it because an IME candidate popup is OS chrome that fires no DOM event in the page. ## Target customer (customer-lens-kickoff, 2026-07-09; evolved 2026-07-12)
**Strategic evolution (Andrew, 2026-07-12; boundary clarified 2026-07-18): the TEAM is now the primary customer.** The team paid service is **Morven**, a separate superset product (all of Raven is in Morven; not all of Morven is in Raven) — Raven itself stays the free open-source tier serving the solo indie dev forever. ### Primary lens — the paying team (2026-07-12)
- We are a product/design team (designers + engineers) with an existing design practice and shared tooling (Slack, Figma, a design system in some state of maturity)
- We are trying to make our design decisions, taste, and system knowledge durable and enforceable across people and AI agents
- But our decisions live scattered in Slack threads, meeting notes, and heads — they get re-litigated and lost
- Because no tool maintains a living, queryable decision/taste graph that both humans and coding agents consult
- Which makes us feel like we're paying a coordination tax on every project
- Meets the product: via a team member (often the indie-dev free user) advocating internally; evaluated with IT/admin approval, procurement, and data-handling questions in the room
- Bounces on: anything requiring broad data access without clear consent controls, unclear data retention/LLM handling, per-seat pricing with no obvious team-level win over the free tier
