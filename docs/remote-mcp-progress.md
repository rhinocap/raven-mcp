## Phase 1 — Stateless remote HTTP (40 tools) on Vercel  ✓ DONE
**Goal:** New HTTP entry, stateless mode (`sessionIdGenerator: undefined`), register ONLY the stateless tools; gate stateful + browser + **filesystem/network/side-effect-capability** tools off in remote mode. No-auth. Secrets via env ONLY.

> **Scope correction (security):** the original 45/20/5 split classified tools by STATE and BROWSER but missed the **capability axis**. FIVE adversarial Codex passes found remote file-read/SSRF/traversal/store/side-effect/input-DoS holes; all five rounds are fixed and re-verified on the live URL (the done bar + reopen rule are in `docs/remote-mcp-scope.md §9`):
> - **Round 1** — 4 "stateless" tools read caller paths (`readFileSync`) or fetch caller URLs on the no-auth endpoint: `audit_contract`, `audit_asset_integrity`, `audit_device_frame` (file-read oracles incl. `/etc/passwd`, `/proc/self/environ`; `/dev/zero` was a `500` DoS), `audit_api_contract` (SSRF). → **gated off entirely** (→ **41** registered, not 45). `audit_page`/`audit_typography` accept a `url` reaching the FS via `file://` capture → **`url` arg rejected in remote mode** (safe html/nodes path kept).
> - **Round 2** — `get_design_system`, `get_content_system`, `compose_system` passed caller `id`/`system` into `loadSystem`/`loadContentSystem` (`join(DIR, id+".json")`), so `id:"../../../../package"` read arbitrary `.json` (path traversal). → **`isSafeDataId()` basename guard** at the loader (rejects `/`, `\`, `..`, leading `.`) — covers all 3 tools + defense-in-depth. Also: usage-log/digest/banner now gated on `!remote` (not the global `VERCEL` env) so stdio is byte-identical under **any** ambient env and the remote path mutates no module-global state; malformed body → `-32700`/`400` (was `500 -32603`).
> - **Round 3** — **local `~/.raven` store oracles.** `score_creative` (optional `brand_profile_id`→`readCreativeRecord`) and the mobile audits `audit_swiftui`/`audit_rn`/`audit_screen`/`audit_ios_screen` (optional `project`/`profile`→`resolveMobileTaste`→`listTasteProfiles`/`resolveSurfaceBinding`) still read the server's LOCAL personal store on the no-auth endpoint. Root cause = the *capability axis* again: the fix stopped chasing per-tool/per-param symptoms and gated the **store capability itself at a choke point**. → **one-way latch** `src/remote-runtime.ts` (`setRemoteRuntime()`/`isRemoteRuntime()`); `buildServer({remote:true})` sets it (monotonic, idempotent under Fluid-Compute reuse, never reset → stdio never sets it → byte-identical). The 5 store functions **fail closed as the FIRST statement** (before any `mkdirSync`): `readCreativeRecord`→null/not-found, `writeCreativeRecord`→throws, `listCreativeRecords`→`[]`, `listTasteProfiles`→`[]`, `resolveSurfaceBinding`→null. Plus an **honest arg-guard layer** (`REMOTE_ARG_GUARDS`): the 5 tools reject `project`/`profile`/`brand_profile_id` in remote mode with a "not available on the hosted endpoint" message rather than silently returning an uncalibrated result. A permanent regression test (`test/remote-store-invariant.test.mjs`) proves the store is readable locally but fully closed in remote mode even with valid on-disk data + explicit project name — the whack-a-mole killer (Fable-designed structural fix). (Approach: Fable-planned Option C + thin A.)
> - **Round 4** — a NEW capability class beyond fs/network/store: **side-effect + unbounded-compute.** (1) `raven_register` was still remote-served and no-auth — its handler POSTs caller-controlled `email`/`name` to the welcome endpoint, which sends mail + subscribes via Resend with no rate-limit/CAPTCHA/auth (a spam/abuse amplifier). → **gated off entirely** (added to `REMOTE_GATED_TOOLS`; fs/network/side-effect group now 5). (2) `evaluate_design` accepts `before_screenshot`/`after_screenshot` as unbounded base64 that flow into `diffScreenshots` (PNG decode + per-pixel loop, no byte/dimension cap) — an unbounded compute/memory sink on the no-auth endpoint. → the two screenshot params **rejected in remote mode** via `REMOTE_ARG_GUARDS` (its description-based principle-matching path stays live). A byte cap inside `diffScreenshots` would also alter the stdio path, so the block is scoped to remote via the guard rather than shared decode code. Net: **41 → 40** remote-served tools.
> - **Round 5** — the broad **input-DoS class (e): unbounded caller-controlled CPU/memory** across 8 core audit tools (`audit_layout`/`audit_screen`/`audit_ios_screen`/`audit_parity`/`audit_typography`/`audit_content`/`audit_consistency`/`generate_service_blueprint`) — each does work proportional to a `z.array()`/`z.string()` input with no cap. These ARE the product (can't be gated) and their schemas are shared with stdio (can't add `.max()` without breaking byte-identity). Root cause = capability axis once more: the *compute* capability is bounded by *input size*, and input size has one choke point — the HTTP body. → **global 400KB request-body byte cap in `api/mcp.js`** (Content-Length short-circuit + authoritative `Buffer.byteLength(JSON.stringify(req.body))`, both before `server.connect`/dispatch; oversize → HTTP 413 / JSON-RPC -32600). One structural fix bounds the *whole class* for all 40 tools (present + future) in a file stdio never loads → byte-identity trivially preserved; no `src/` change. The real threat closed is **billed-CPU cost amplification** on a no-auth Fluid-Compute endpoint (the 300s timeout is no defense — burned CPU *is* the attack). Fable-designed structural fix + the **STOP bar / falsifiability reopen rule** now recorded in `docs/remote-mcp-scope.md §9` — the input-DoS class is CLOSED (no fs/net/store/side-effect sink + all input ≤400KB pre-dispatch + no super-polynomial-in-bytes blowup + bounded output); "large input → proportional work" is definitionally not a reopener. **Cap tightened 1MB→400KB in round 6:** r6 (falsification pass) returned DONE-IS-TRUE but measured the worst O(n²) hot path (`audit_page` `@media` regex, `page-checks.ts:75`) at **68.1s @ 980KB** — passing the STOP bar (polynomial, <300s, no sink) but falsifying the "worst case seconds" assumption behind the 1MB value; Fable re-derived 400KB from the measured quadratic (→ **~11s** worst case, ~38× a normal audit vs ~227× at 1MB) while clearing the ~260KB LLM-client tool-call ceiling. Concurrency/volumetric flooding → **Vercel WAF rate rule** (ops, non-blocking; not a code fix).
