01

Get Started

RavenMCP is a design-intelligence MCP server. Install it, point your coding agent at it, and it audits pages/layouts/screens, generates design systems and tokens, and carries your taste across projects.

1

Install

One command, or add the server to your MCP client config by hand.

npx @ravenmcp/cli install 
// manual config — .mcp.json
{
  "mcpServers": {
    "raven": {
      "command": "npx",
      "args": ["-y", "raven-mcp"]
    }
  }
}
2

Connect

Restart your agent. Raven's 70 tools are now available.

$ raven doctor
✓ server reachable · ✓ 70 tools registered
✓ 9 knowledge layers loaded
3

Use it

Ask your agent to audit a page, generate a design system, or check contrast; it calls the right tool automatically.

› "audit this pricing page for contrast issues"
→ raven.audit_contrast · 2 findings · fixes attached

Tool Reference

Raven provides 70 tools across 9 knowledge layers. Claude calls the relevant tool based on the task; the entries below show what each tool returns.

Principles

3 of 8 tools shown
get_principles#

Get design principles relevant to a UI context. Returns usability heuristics, Laws of UX, Gestalt principles, accessibility rules, typography, color theory, mobile UX, and responsive layout.

Parameters
contextrequiredstring

What you're designing — e.g. "signup form", "pricing page", "mobile nav", "dark dashboard"

categoryoptionalstring

Filter to: nielsen-heuristics, laws-of-ux, gestalt, accessibility, typography, color-theory, mobile-ux, responsive-layout, d4d

formatoptionalstring

"full" (default) | "checklist" | "brief"

you say

"Build a pricing page"

"What accessibility rules apply to forms?"

"Check this against Nielsen's heuristics"

raven returns
{
  "principles": [
    { "id": "lawsofux.hicks-law",
      "applies": "limit visible plan
        options to 3–4" },
    { "id": "a11y.focus-order", … }
  ],
  "format": "checklist"
}
evaluate_design#

Evaluate a design description against UX principles. Returns relevant principles, potential violations, and improvement suggestions.

Parameters
descriptionrequiredstring

Description of the design to evaluate

contextoptionalstring

What the design is — e.g. "pricing page for SaaS product"

goalsoptionalstring[]

Array of evaluation goals — e.g. ["conversion", "accessibility", "mobile-usability"]

you say

"This signup form has 8 fields, no social login, and the button says Submit. Evaluate it for conversion."

raven returns
{
  "violations": [
    { "rule": "forms.field-count",
      "note": "8 fields ≈ 2× the
        conversion-optimal count" },
    { "rule": "cta.label-specificity",
      "fix": "'Create account',
        not 'Submit'" }
  ]
}

audit_contrast#

Check color pairs against WCAG contrast requirements. Returns pass/fail per pair with measured ratios and the nearest passing color for each failure.

Parameters
pairsrequiredarray

Foreground/background pairs — [{ fg, bg, size? }]. Accepts hex, rgb, or CSS custom property references when a page is attached.

leveloptionalstring

"AA" (default) | "AAA"

you say

    "ratio": 4.05,
    "required": 4.5,
    "pass": false,
    "nearest_pass": "#747481"
  }]
}

Examples

Three real exchanges. You talk to your agent; the agent talks to Raven. Nothing else to learn.

exchange 01 · audit_contrast
you
"Audit this pricing page for contrast issues."
agent → raven
audit_contrast({ pairs: from page CSS, level: "AA" })
raven → agent
error3.1:1 on .tier-note — needs 4.5:1. Fix: lighten to #8a8a96
warn4.6:1 on .badge-popular — passes AA, fails AAA
info7 pairs checked, 5 clean
exchange 02 · get_principles
you
"What should I watch for in this signup form?"
agent → raven
get_principles({ context: "signup form", format: "checklist" })
raven → agent
checkLabel every field — placeholders are not labels
checkInline validation on blur, not on submit

exchange 03 · generate_design_system
you
"Set up tokens for the new marketing site — same brand, warmer."
agent → raven
generate_design_system({ brief: "marketing site, warmer", seed: { colors: existing brand } })
raven → agent
42 tokens written to tokens.css — hue shifted +8° warm, type scale and spacing preserved from the bound project profile.

04

Data Structure

Every audit returns a structured object: findings[] (each with severity, rule, location, fix), a summary score, and calibration_hint when a taste profile is bound.

summary — score 0–100, letter grade, counts by severity
findings[] — one entry per issue; fix is always concrete enough for the agent to apply directly
calibration_hint — present only when a taste profile is bound; explains what the profile changed about the verdict
{
  "summary": {
    "score": 82,
    "grade": "B",
    "counts": { "error": 1, "warning": 3, "info": 2 }
  },
  "findings": [
    {
      "severity": "error",
      "rule": "contrast.aa.normal-text",
      "location": ".pricing-tier .price-note",
      "value": "3.1:1",
      "required": "4.5:1",
      "fix": "Raise --text-tertiary to #8a8a96 on this surface."
    }
  ],
  "calibration_hint": "Bound profile prefers hierarchy via weight over size — two findings suppressed."
}

05

Design Tokens

Raven generates a full token set — color, type, spacing, radius — from a brief or an existing brand. Bound taste profiles apply per-project overrides, so the same brief produces different tokens for different people.

base
surface
accent
text
color — base/surface/raised backgrounds, three text tiers, one accent family
space — a single multiplier scale; no orphan values
overrides — what the bound profile changed, kept separate so they're auditable
{
  "color": {
    "bg-base": "#0b0e12",
    "bg-surface": "#141922",
    "text-primary": "#e8ebef",
    "text-secondary": "#9aa3ad",
    "accent": "#4f8fdb"
  },
  "space": {
    "1": "4px", "2": "8px", "3": "12px",
    "4": "16px", "6": "24px", "8": "32px"
  },
  "overrides": {
    "source": "taste-profile:andrew",
    "radius-md": "8px → 6px"
  }
}

06

FAQ

Does this replace a design system?

No. It enforces the one you have and helps generate one where you don't. Your tokens stay the source of truth.

Does it work with any coding agent that supports MCP?

Yes. Anything that speaks MCP — Claude Code, Cursor, Codex, Windsurf — gets the same 70 tools.

Is my design data used to train models?

No. Audits run against a local knowledge base; taste profiles live in your own storage and can be deleted at any time.

What's the difference between the free and team tier?

The free tier is the full open-source server, forever. The team tier adds shared taste profiles, a decision graph your whole team's agents consult, and admin controls.

Can I self-host?

Yes. The server is open source and runs locally over stdio by default — self-hosting is the default, not a tier.
