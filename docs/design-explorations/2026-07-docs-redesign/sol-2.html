01 / establish connection

Get Started

RavenMCP is a design-intelligence MCP server. Install it, point your coding agent at it, and it audits pages, layouts, and screens, generates design systems and tokens, and carries your taste across projects.

Install

npx @ravenmcp/cli install, or add Raven to your MCP client config manually.

Connect

Restart your agent. Raven’s 70 tools are now available.

Use it

Ask your agent to audit a page, generate a design system, or check contrast. It calls the right tool automatically.

mcp.json / manual config
{
  "mcpServers": {
    "raven": {
      "command": "npx",
      "args": ["-y", "raven-mcp"]
    }
  }
}

Tool Reference

Raven provides 70 tools across 9 knowledge layers. Claude calls the relevant tool based on the task; the records below show what each tool returns.

Principles Layer

6 selected records

get_principles

knowledge query

Get design principles relevant to a UI context. Returns usability heuristics, Laws of UX, Gestalt principles, accessibility rules, typography, color theory, mobile UX, and responsive layout.

Input parameters

context stringrequired
What you’re designing — e.g. “signup form”, “pricing page”, “mobile nav”, “dark dashboard”.
category enumoptional
Filter to: nielsen-heuristics, laws-of-ux, gestalt, accessibility, typography, color-theory, mobile-ux, responsive-layout, d4d.
format enumoptional
“full” (default) | “checklist” | “brief”.

Agent prompts

› Build a pricing page
› What accessibility rules apply to forms?
› Check this against Nielsen’s heuristics

evaluate_design

principle evaluation

Evaluate a design description against UX principles. Returns relevant principles, potential violations, and improvement suggestions.

Input parameters

description stringrequired
Description of the design to evaluate.
context stringoptional
What the design is — e.g. “pricing page for SaaS product”.
goals string[]optional
Array of evaluation goals — e.g. [“conversion”, “accessibility”, “mobile-usability”].

Agent prompt

› This signup form has 8 fields, no social login, and the button says Submit. Evaluate it for conversion.

get_d4d_framework

framework template

Get Design for Delight (D4D) templates — customer problem statement, ideal state, hypothesis, LOFAs, and experiment design.

Input parameters

stage enumoptional
“frame” | “empathy” | “broad” | “narrow” | “experiment”.

Agent prompt

› Frame a testable customer problem for this onboarding drop-off.

audit_page

page audit

Inspect rendered HTML for accessibility, hierarchy, interaction, responsive layout, and visual-quality issues. Returns located findings with concrete fixes.

Input parameters

html stringrequired
The relevant rendered HTML or component markup.
viewport objectoptional
Width, height, and device context for responsive checks.
checks string[]optional
Limit the audit to contrast, tap-targets, typography, layout, or accessibility.

Agent prompt

› Audit the pricing route at mobile and desktop widths before I merge it.

generate_design_system

system generation

Generate a coherent token foundation and component guidance from a product brief, existing brand, or reference interface.

Input parameters

brief stringrequired
Product context, audience, visual constraints, and desired character.
source objectoptional
Existing colors, type choices, screenshots, or a known design system.
format enumoptional
“dtcg” | “css” | “json”.

Agent prompt

› Build a restrained token set for a clinical scheduling product from this brand sheet.

map_service_blueprint

service design

Map customer actions, visible touchpoints, backstage operations, handoffs, and failure points into a structured service blueprint.

Input parameters

journey stringrequired
The customer journey or service moment to map.
actors string[]optional
Customers, staff, systems, and partners involved.
depth enumoptional
“overview” | “handoffs” | “full”.

Agent prompt

› Map the handoffs between support, design, and engineering after a customer reports a UI defect.

04 / read payload

Data Structure

Every audit returns a structured object: findings[] (each with severity, rule, location, fix), a summary score, and calibration_hint when a taste profile is bound.

The shape stays consistent across page, screen, layout, and taste audits, so agents can act on the result without parsing prose.

  1. 01findings[]
  2. 02summary.score
  3. 03calibration_hint
audit response / application.json
{
  "findings": [
    {
      "severity": "high",
      "rule": "text-contrast-aa",
      "location": ".pricing-card .price-note",
      "observed": "2.7:1",
      "fix": "Use --text-secondary; expected 5.1:1"
    }
  ],
  "summary": {
    "score": 82,

06 / resolve questions

FAQ

Short answers to the questions that tend to come up before Raven is added to a project or team workflow.

Does this replace a design system?
No. Raven can generate or inspect tokens and patterns, but your design system remains the source of truth. Raven helps agents apply it and flag drift.
Does it work with any coding agent that supports MCP?
Yes. Raven uses the Model Context Protocol and can be added to compatible clients through their standard MCP configuration.
Is my design data used to train models?
No. The local server runs in your environment and does not use project data for model training. Hosted and team deployments document their retention and consent controls separately.
What’s the difference between the free and team tier?
The free tier provides the local design-intelligence tools for individual work. Team adds shared taste, decision history, permissions, and administrative controls.
Can I self-host?
Yes. The open-source server can run locally or in infrastructure you control. Hosted features that depend on managed identity or shared storage require equivalent services.
