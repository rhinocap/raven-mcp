01 / ENTRY

Get Started

RavenMCP is a design-intelligence MCP server. Install it, point your coding agent at it, and it audits pages/layouts/screens, generates design systems and tokens, and carries your taste across projects.

01

Install

npx @ravenmcp/cli install (or add to your MCP client config manually)

02

Connect

restart your agent, Raven's 70 tools are now available

03

Use it

ask your agent to audit a page, generate a design system, or check contrast; it calls the right tool automatically.

mcp-client.json
{
  "mcpServers": {
    "raven": {
      "command": "npx",
      "args": ["-y", "raven-mcp"],
      "env": {
        "RAVEN_FORMAT": "structured"
      }
    }
  }
}
Terminal
$ npx @ravenmcp/cli install
02 / METHODS

Tool Reference

Raven provides 70 tools across 9 knowledge layers. Claude calls the relevant tool based on the task; the cards below show what each tool returns.

Principles Layer

get_principles

Get design principles relevant to a UI context. Returns usability heuristics, Laws of UX, Gestalt principles, accessibility rules, typography, color theory, mobile UX, and responsive layout.

Parameters
contextrequiredstring
What you're designing — e.g. "signup form", "pricing page", "mobile nav", "dark dashboard"
categoryoptionalenum
Filter to: nielsen-heuristics, laws-of-ux, gestalt, accessibility, typography, color-theory, mobile-ux, responsive-layout, d4d
formatoptionalenum
"full" (default) | "checklist" | "brief"
Example usage
  • Build a pricing page
  • What accessibility rules apply to forms?
  • Check this against Nielsen's heuristics
Show response fields

principles[], checklist[], sources[], context

Agent call
get_principles({
  context: "pricing page",
  format: "checklist"
})

evaluate_design

Evaluate a design description against UX principles. Returns relevant principles, potential violations, and improvement suggestions.

Parameters
descriptionrequiredstring
Description of the design to evaluate
contextoptionalstring
What the design is — e.g. "pricing page for SaaS product"
goalsoptionalstring[]
Array of evaluation goals — e.g. ["conversion", "accessibility", "mobile-usability"]
Example usage
  • This signup form has 8 fields, no social login, and the button says Submit. Evaluate it for conversion.
Show response fields

score, violations[], suggestions[], principles[]

Agent call
evaluate_design({
  description: "8-field signup…",
  goals: ["conversion"]
})

get_d4d_framework

Get Design for Delight (D4D) templates — customer problem statement, ideal state, hypothesis, LOFAs, and experiment design.

Parameters
stageoptionalenum
"frame" | "empathy" | "broad" | "narrow" | "experiment"
Example usage
  • Frame the customer problem before we sketch solutions
  • Turn these interview notes into testable LOFAs
Show response fields

stage, template, prompts[], quality_checks[]

Agent call
get_d4d_framework({
  stage: "experiment"
})

audit_page

Audit a rendered page for layout, typography, contrast, hierarchy, responsive behavior, and interaction quality. Returns located findings with direct fixes and a scored summary.

Parameters
urlrequiredstring
Public or local URL to inspect
viewportoptionalobject
Width and height for the rendered audit; defaults to desktop
focusoptionalstring[]
Limit findings to contrast, layout, type, accessibility, motion, or responsive behavior
Example usage
  • Audit localhost:3000/pricing at a 390px viewport
  • Find only contrast and hierarchy issues on this page
Show child parameters

viewport.width and viewport.height accept integer CSS pixels. Add deviceScaleFactor when capture density matters.

Agent call
audit_page({
  url: "http://localhost:3000",
  viewport: { width: 390, height: 844 }
})

generate_design_system

Generate a usable design-system foundation from a product brief or existing brand. Returns semantic color, type, spacing, radius, component guidance, and implementation-ready tokens.

Parameters
briefrequiredstring
Product, audience, platform, and visual intent
sourceoptionalobject
Existing brand colors, fonts, screenshots, or token values to preserve
formatoptionalenum
"css" | "json" | "tailwind" | "figma"
Example usage
  • Generate a calm clinical dashboard system from these two brand colors
  • Convert this brief into CSS custom-property tokens
Show child parameters

source.colors[], source.fonts[], source.assets[], and source.constraints[] are accepted.

Agent call
generate_design_system({
  brief: "Clinical dashboard…",
  format: "css"
})

audit_service_blueprint

Review a service blueprint across customer actions, frontstage touchpoints, backstage processes, handoffs, and failure recovery. Returns continuity gaps and accountable next actions.

Parameters
blueprintrequiredobject
Stages, actors, customer actions, touchpoints, processes, and support systems
lensoptionalenum
"continuity" | "ownership" | "failure-recovery" | "accessibility"
constraintsoptionalstring[]
Operational or policy conditions the service must honor
Example usage
  • Find ownership gaps in this support escalation blueprint
  • Audit what happens when identity verification fails
Show child parameters

Each blueprint.stage can include customer_actions[], frontstage[], backstage[], and systems[].

Agent call
audit_service_blueprint({
  blueprint: supportFlow,
  lens: "ownership"
})
03 / EXCHANGES

Examples

The agent provides context; Raven selects the relevant knowledge layer and returns findings that can be acted on directly.

Promptaudit_page
“Audit this pricing page for contrast issues.”
Response3 findings · 76/100

Two text pairs fail WCAG AA; one focus state relies on color alone.

High

Annual price label · 2.9:1 on #12181c. Use --text-secondary or raise lightness to 72%.

Medium

Plan selector · Add a 2px outline so keyboard focus does not rely on cyan alone.

Promptgenerate_design_system
“Create tokens for a calm, high-trust health dashboard. Keep our blue.”
Response48 tokens · CSS

Preserved the source blue as the action color, built neutral surfaces around it, and generated type, spacing, radius, and state scales.

Output

color.action.primary → #3478F6 · space.4 → 16px · radius.control → 8px

Promptevaluate_design
“This onboarding asks for company size before showing value. Evaluate the sequence.”
Response4 principles

The sequence asks for commitment before establishing relevance.

Sequence

Move company-size collection after the first useful output, or state why it changes the result.

Measure

Compare first-value completion and abandonment at the company-size step.

04 / RESPONSE

Data Structure

Every audit returns a structured object: findings[] (each with severity, rule, location, fix), a summary score, and calibration_hint when a taste profile is bound.

Stable audit anatomy
  • findings[] keeps evidence and remediation together.
  • summary.score supports comparison without hiding individual issues.
  • calibration_hint explains when project taste altered the evaluation.
audit-response.json
{
  "findings": [
    {
      "severity": "high",
      "rule": "wcag-contrast-aa",
      "location": ".plan-card .price-note",
      "fix": "Raise text contrast from 2.9:1 to 4.5:1"
    }
  ],
  "summary": {
    "score": 76,
    "counts": { "high": 1, "medium": 2 }
  },
  "calibration_hint": "Applied raven-mcp project taste: restrained product-site voice"
}
05 / SYSTEM

Design Tokens

Raven can generate a full token set (color, type, spacing, radius) from a brief or existing brand, and bound taste profiles apply per-project overrides.

Semantic before literal

Generated scales keep raw values separate from the roles that consume them. Existing brand inputs remain traceable in the output.

surface / base
surface / raised
action / primary
accent / cyan
text / primary
tokens.json
{
  "color": {
    "surface": { "base": "#0B0F12", "raised": "#152029" },
    "action": { "primary": "#3F75FF" },
    "text": { "primary": "#F5F8FA", "muted": "#9BA8B1" }
  },
  "space": {
    "1": "4px", "2": "8px", "3": "12px",
    "4": "16px", "6": "24px", "8": "32px"
  }
}
06 / NOTES

FAQ

Operational details about where Raven fits, what it reads, and how it can be run.

Does this replace a design system?

No. Raven can generate and audit a system, but your tokens, components, governance, and product decisions remain the source of truth.

Does it work with any coding agent that supports MCP?

Yes. Add Raven as an MCP server in any compatible client. Tool selection and approval behavior depend on that client.

Is my design data used to train models?

No. Raven does not use your project inputs to train models. Review the model provider configured in your environment for its separate data-handling terms.

What's the difference between the free and team tier?

The free tier serves an individual builder with local tools. The team tier adds shared taste and decision context, administration, and controls for organizational data.

Can I self-host?

Yes. The open-source server runs locally over stdio. Hosted identity, team storage, and managed collaboration features are separate.
